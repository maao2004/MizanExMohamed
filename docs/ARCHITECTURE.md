# معمارية منصة ميزان (MizanEX Architecture)

## 1. القواعد الدائمة للبناء والحوكمة
1. **مصدر الحقيقة الوحيد (Single Source of Truth):**
   - `quarterly_financial_records`: المرجع الوحيد لاشتقاق قائمة الأسهم المتاحة وهويتها وتواريخ فتراتها المالية (تُستخدم `financials` كإسقاط متزامن لنفس السجلات).
   - `daily_trading_records`: المرجع الوحيد للأسعار السوقية وتواريخ التداول وأحجام التداول اليومية. لا تُخلق أي سجلات لعطلات أو تواريخ غير موجودة في الملفات، ولا يُستبدل السعر السوقي كبديل للقيمة العادلة.
   - `beta_assumptions/{ticker}`: المرجع المعتمد الوحيد لمعامل `Beta` لكل سهم (`betaRaw`)، وبيتا المعدلة (`betaAdjusted`) مشتقة فقط منه + (`Beta_Raw_Weight`, `Beta_Anchor`).
   - `macro_params/{key}`: المرجع المعتمد الوحيد للمعاملات العامة (Global Scope).
   - `company_assumptions/{ticker}/parameters/{key}`: المرجع المعتمد الوحيد لتخصيصات المعاملات الخاصة بالشركة (Company Scope).
2. **منع البيانات التجريبية والبدائل الصامتة:**
   - لا توجد أسهم افتراضية (`INITIAL_COMPANIES`) ولا معاملات تجارية مزروعة داخل الكود (`DEFAULT_MACRO_PARAMETERS`) ولا أزرار استعادة أمثلة.
   - القيم الفارغة (`BLANK` / `null`) لا تُستبدل بالصفر، والصفر الفعلي (`0`) لا يُعامل كقيمة مفقودة.
   - **الاستثناء الوحيد المسموح:** تساوي بيتا الخام `1` (`betaRaw = 1` أو حسب سياسة `Beta_Default` الموثقة) **فقط بعد تأكيد الخادم** عدم وجود سجل صالح للسهم في `beta_assumptions` (ولا يُطبق هذا الافتراض إطلاقاً عند انقطاع الاتصال أو نقص الصلاحية أو تلف سجل البيتا).
3. **الفصل الطبقي الصارم (Layered Modular Architecture):**
   - `src/core/contracts/*`: العقود القياسية المشتركة (التطبيع، التجزئة الحتمية `contentHash`، سجل المعاملات المركزي، التحقق والإسقاط) — مع نسخة مطابقة ومستقلة في `functions/src/shared/*` دون أي استيراد عابر لحدود البناء بين الواجهة والخادم.
   - `src/core/math/*`: الحسابات المالية النقية (`valuation.ts`, `healthChecks.ts`) بدون أي وصول للشبكة أو Firestore.
   - `src/core/domain/*`: منطق المجال وتكوين الافتراضات واشتقاق الأسهم وإدارة جلسات المزامنة.
   - `src/core/imports/*`: معالجات استيراد Excel للمصادر الأربعة، بناء المعاينة (`Preview Diff`) دون أي كتابة، والتنفيذ عبر دفعات مجزأة.
   - `src/repositories/*`: طبقة الوصول لقاعدة البيانات والمزامنة التزايدية عبر `serverUpdatedAt` و`tombstones` والكاش المعزول حسب المشروع والمستخدم.
   - `src/hooks/*`: فصل إدارة الجلسة ومسار التقييم عن `App.tsx`.
   - `src/modules/data-hub/*` & `src/components/*`: واجهات عرض وتفاعل خالصة تستقبل البيانات وتفوض حالات الاستخدام.
4. **أمن القواعد والكتابات الحساسة:**
   - جميع عمليات الاستيراد والكتابات المالية والمصادر الأربعة وتعديلات المعاملات والبيتا والحذف تتم حصرياً عبر Cloud Functions (`Admin SDK`) مع التحقق من المصادقة والدور الفعلي.
   - قواعد `firestore.rules` تحمي `beta_assumptions` و`company_assumptions` و`import_batches` و`tombstones` بمنع الكتابة المباشرة من العميل (`allow write: if false`).

## 2. تدفق المزامنة التزايدية وإدارة الجلسات
- عند تسجيل الدخول أو تغير `uid` تبدأ جلسة معزولة برمز (`SessionToken`) ومفاتيح كاش مقيدة بـ `projectId + databaseId + uid + schemaVersion`.
- تُسجل اللقطات عبر `onSnapshot(..., { includeMetadataChanges: true })` وتُميَّز حالة `loading` عن `offline` عن `permission_denied` عن `empty` المؤكد من الخادم.
- تستخدم المزامنة التزايدية مؤشر (`cursor`) يعتمد على `serverUpdatedAt` (`Firestore Timestamp`) بالاستعلام الأحادي المفهرس تلقائياً (`where('serverUpdatedAt', '>=', cursor)` مع `orderBy('serverUpdatedAt', 'asc')`) للحد من تكرار قراءة المجموعات كاملة.
- الحذف يولّد سجلات شواهد في `tombstones` بنافذة احتفاظ (30 يوماً)؛ وعند غياب المؤشر أو انتهاء نافذة الاحتفاظ يجري التطبيق إعادة مواءمة كاملة نظيفة من الخادم (`getDocsFromServer`) لمنع عودة السجلات المحذوفة من الكاش.

## 3. تقدير التكاليف الواقعي للقراءة والكتابة في Firestore
| العملية | القراءات (Reads) | الكتابات (Writes) |
|---|---|---|
| تهيئة جلسة جديدة أو انتهاء نافذة Tombstones (30 يوماً) | مجموع وثائق المجموعات النشطة مرة واحدة | 0 |
| المزامنة التزايدية اللاحقة | الوثائق المتغيرة منذ `cursor` + الشواهد المتغيرة فقط (`>= 0`) | 0 |
| إعادة استيراد ملف متطابق (Idempotent Re-import) | قراءة الوثائق المستهدفة بالدفعة للتحقق من `contentHash` | **0 كتابة فعلية** للمستندات غير المتغيرة |
| استيراد/تحديث $K$ سجل مالي فصلي | $K$ قراءة للتحقق | $2K$ كتابة (`quarterly_financial_records` + `financials`) + 1 سجل دفعة (`import_batches`) |
| استيراد $K$ سجل تداول أو بيتا أو معاملات | $K$ قراءة للتحقق | $K$ كتابة + 1 سجل دفعة |
| حذف وثيقة واحدة | 1 قراءة | 1 حذف (+ حذف إسقاط `financials` للربع المالي) + 1 شاهد في `tombstones` |
